In plain terms

This project evolves small grids of simple, spiking "neurons" — each one just adds up pulses from its neighbors, fires in a genetically-fixed direction once it crosses a threshold, then rests for a cycle before it can fire again. A grid of these neurons is called a chunk. Nothing is hand-programmed to route or "remember" anything: a genetic algorithm randomly mutates each neuron's routing/threshold genes and keeps whichever variant scores better against a target input→output task, generation after generation.

The rest of this page is a live window into that system, reading real state from the C++ / Verilog simulators running behind it — nothing here is a canned mockup.

  • Single chunk: watch one grid of neurons accumulate, fire, and rest; edit a neuron's genes by hand and see the effect immediately.
  • Evolution: run the genetic search and see the fitness function's actual per-cycle behavior, not just one final number.
  • Multi-chunk · C_LINK: the project's newer, in-progress direction — wiring several chunks together (a memory chunk, an input chunk, a cortex chunk, an output chunk) with the C_LINK interconnect primitive described in CURRICULUM.md. This section shows exactly how far that wiring has actually progressed right now — including labeling any chunk that hasn't been trained yet, rather than hiding it.

How one neuron works — accumulate → fire → refractory:
  1. Every cycle, a neuron adds any incoming pulses (from its N/E/S/W neighbors, plus an external input row on the top edge) to its own charge.
  2. Once that charge reaches its genetically-set threshold (1, 3, 5, or 7), it fires: it emits a pulse toward whichever of its 4 directions its 4-bit "mask" gene selects, its charge resets to 0, and only the south-firing bit reaches the grid's output edge on the bottom row.
  3. The cycle right after firing is a refractory period — it cannot accumulate or fire again until the cycle after that.

This runs a (1+λ) hill-climb over the same chunk shown in the Single chunk tab: each generation mutates the current best genome ~24 ways, keeps whichever candidate scores higher against the wanted-output row. Fitness blends the worst cycle in the evaluation window (60%) with the average cycle (40%) — a worst-cycle floor so a genome can't hide a bad cycle behind a couple of lucky ones — plus an accumulator-distance tiebreaker when two genomes tie on integer fitness. The first YS-1 cycles are excluded as warm-up (pulses haven't reached the bottom row yet).
